## 2. Part 1 の勝ち方

### ルール
- 自分の環境で実装。**画面全体を共有**（単一ウィンドウ不可）
- 疑似コードではなく**動くソフトウェア**
- 仕様確認は任意。前提を宣言して進めてよい
- **30分時点で動くものを**。完成は「最低ライン」で、評価の本体はその後の議論

### 評価軸（ガイドの表）
スコーピングと実行力 / 問題解決 / 技術的深さ / 適応力（要件変更への対応）/ エンジニアリング判断 / **ツールのオーナーシップ**

### 戦略
1. **最初の2分で計画を宣言**：「まず X の最小構成を動かし、時間があれば Y を足します。前提は A・B です」
2. **縦に薄く切る**。全機能を半端に作るより、1本のフローが端から端まで動く方が強い
3. **20分で動かす**（30分は締切、目標は20分）。バッファを持つ
4. こまめに git commit。プロセスが見える
5. テストは1〜2本だけ書き、「本番ならこれとこれも足す」と口で補う
6. **議論に25分以上残す**。ここが本番

### 要件変更が来たら
慌てず「変更点を復唱 → 設計への影響を述べる → 最小の変更で対応」。適応力はガイドに明記された評価軸。

### 議論で聞かれる論点（先に1〜2文ずつ用意）
データモデリングとデータ構造の選択 / モジュール性と保守性 / エッジケースと業務文脈 / テストと本番運用 / 性能とスケール / セキュリティ / 代替案とトレードオフ

「理由 → 代替 → トレードオフ → この文脈では妥当」の型で答える。

## 3. AI の使用（Mercari と真逆・許可されている）

- **使ってよい**：IDE、ドキュメント、検索、AI アシスタント
- **避けるよう推奨**：Superpowers、Matt Pocock skills、GSD などの重量級エージェント的ワークフロー。計画・コンテキスト・セットアップの overhead で実装時間を食い潰すため（禁止ではなく助言）
- **評価される形**：ツールで速く動きつつ、**理解・判断・結果の所有権を保つ**

実践：
- 生成されたコードは必ず読んでから採用。説明できないコードは使わない
- 「ここは定型部分なのでアシスタントに書かせて、レビューして使います」と口に出す。オーナーシップの証明になる
- 軽量構成（補完 + チャットで調べ物）が最適

## 4. Part 2：行動面接 + 日本語チェック

聞かれるテーマ：協働と対立 / オーナーシップ / メンタリングと技術リード / 複雑なプロジェクトの遂行 / 不確実性下の意思決定 / 失敗と学び / チーム文化への貢献

評価軸：内省 / 協働 / オーナーシップ / 具体性 / 文化的貢献

用意する STAR 3〜5本（各2分）：
1. 対立の解消（技術選定や優先度で意見が割れた）
2. オーナーシップ（本番障害や納期危機を引き受けた）
3. メンタリング / 技術リード（SoftBank のインターン・初級メンバー指導、19リポジトリのセキュリティ修正主導）
4. 不確実性下の判断（要件が曖昧なまま前提を置いて進めた）
5. **失敗と学び**（Canlah の本番障害 → 根本原因を恒久的な防御に固定化）

日本語チェック：N1 保有。技術説明を日本語でできるかを見られるので、自己紹介と直近プロジェクトの説明を日本語で1回声に出しておく。

## 5. 事前セットアップ（ガイドのチェックリスト + 実務上の注意）

### 最大のリスク：会社PCでは無理
「画面全体を共有」「自分の IDE」「依存関係のインストール」「Docker / DB」「AI ツールにサインイン」——これを会社PCでやるのは、
- 業務情報が画面全体に映る
- IT ポリシーでインストールや Docker が制限される可能性
- 個人の AI アカウントに会社PCでサインインするのは規程違反になり得る

→ **個人PCで受けること。** 10/7〜10/9 なら帰国後なので自宅の個人PCで問題ない。

### 当日までに確認
- [ ] 個人PCで「画面全体」の共有ができる（単一ウィンドウではなく）。Zoom/Teams/Meet のどれか事前にテスト
- [ ] モニタ2枚なら、全体共有時にどう見えるか確認。1枚に絞る方が安全
- [ ] IDE（VS Code など）が開いてすぐ使える
- [ ] **Hello World が動く雛形**：Python なら FastAPI + uvicorn + pytest が `run` 一発で動く状態
- [ ] 依存関係がインストールできる（venv / uv、ネットワーク確認）
- [ ] Docker Desktop 起動、postgres などのイメージを事前 pull
- [ ] git init 済み
- [ ] AI ツールにサインイン済み、軽量構成
- [ ] 通知オフ、デスクトップを整理（**画面全体が映る**ので個人的なものを閉じる）
- [ ] ブラウザのタブを整理、別アカウントのメール等を閉じる
