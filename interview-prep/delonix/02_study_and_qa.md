### 3. Java / Spring 复习（20 分钟，够应付提问即可）
- Spring Boot：starter 自动装配、@RestController / @Service / @Repository、@Transactional、配置 profile、Actuator 健康检查
- Spring Cloud：注册中心（Nacos / Eureka）、OpenFeign 服务调用、Gateway 网关、Sentinel / Resilience4j 熔断限流、配置中心
- WebFlux：Reactor 的 Mono / Flux，非阻塞、事件驱动，适合 IO 密集高并发（如大量工单推送、外部 API 聚合）；不适合 CPU 密集和阻塞 JDBC（需 R2DBC）；调试和背压是难点
- 接口治理：OpenAPI 契约、版本、幂等键（Idempotency-Key）、限流、统一错误码、审计日志
- 稳定性：超时 / 重试 / 熔断 / 降级、灰度发布、回滚预案、监控告警

### 4. LangGraph 概念（10 分钟）
- StateGraph：节点（函数）+ 边（含条件边）+ 共享状态；checkpointer 持久化状态
- **interrupt / human-in-the-loop**：图在某个节点暂停等人审批后继续。这正好对应"高风险操作审批链路"，面试可以主动提
- 和 LangChain 的关系：LangChain 是组件库，LangGraph 是有状态编排

### 5. 指标口径（10 分钟）
- 一次性完成率 = 无人工介入且无返工完成的工单 / 全部工单
- 人工介入率 = 需要人接手的工单 / 全部工单
- 差错率 = 结果错误（错派、错答、错操作）的工单 / 全部工单
- 平均响应时长 / 完成时长、SLA 达成率、客诉率
- 讲法：先定基线 → 试点 1–2 店 → 周维度看指标 → 问题回流到规则 / 知识 / 工具契约 → 规模复制

## 二、预测问题与答案要点

- 关于地点：坦白目前在东京，问清岗位地点与远程政策（这是你要问的，也是他们会问的）

**Q3 你没有酒店行业经验，怎么看这个硬门槛？**

- 说明 Agent 化的通用方法论不依赖行业：业务对象建模 → 工具契约 → 人机边界 → 指标闭环

### B. 酒店业务理解
**Q4 讲一下你理解的神灯客需处理链路，哪些该 AI 做？**
客需 → 意图与紧急度识别（AI）→ 查房态 / 客人信息（AI 调工具）→ 建工单（AI）→ 分派（规则 + AI 建议，按部门、位置、负荷）→ 执行（人）→ 进度追踪与催办（AI）→ 回访关闭（AI）。涉及退款、补偿、改价、投诉升级 → 转人工。SLA 超时 → 自动升级值班经理。

**Q5 PMS 里哪些操作是高风险的，为什么？**
改价（影响收益与渠道一致性）、退款 / 调账（涉及资金和账务平衡）、房态变更（影响可售房量与超售）、夜审期间的任何账务操作（日切中）。风险来自：不可逆、影响面大、涉及资金、跨系统同步。

**Q6 门店之间 SOP 不一样，知识怎么管？**
总部 SOP 作为基线版本；门店差异做覆盖层，单独版本；检索时按门店 ID 合并；变更走审核并可回溯；用验收案例回归，防止改一处坏全局。

### C. 业务抽象与人机边界
**Q7 怎么设计 Agent 的人机边界？**
按风险分三级（只读自动 / 低风险写操作自动 + 抽检 / 高风险写操作人审批）；工具契约里声明副作用等级与可逆性；幂等键；全部写操作留痕；Agent 以调用人的权限执行；LLM 置信度低或不可用 → 回退规则或转人工。可以提 LangGraph 的 interrupt 实现审批暂停。

**Q8 什么是好的工具契约？举个例子。**
输入输出 schema、副作用声明、幂等、超时与降级、错误码、版本。例子：Canlah 的 30 路径 OpenAPI 契约冻结为唯一外部边界，8 个 JSON Schema，任务台账状态机做幂等去重，98 个单元测试作为验收案例。

**Q9 Skill（技能）和 Tool 的区别，怎么做版本管理？**
Tool 是原子能力（查房态、建工单）；Skill 是把业务规则 + 多个 Tool 编排成一个可复用能力（"处理加床请求"）。版本管理：Skill 有 semver、配套验收案例、灰度发布、回滚。

### D. AI 工程
**Q10 RAG 怎么做切分和检索，怎么保证可回溯？**
按业务单元切分（一条 SOP、一条规则）而不是固定长度；元数据（门店、版本、生效日期）；混合检索（关键词 + 向量）；回答附来源 ID；知识更新走版本与审核；用评测集做回归。SoftBank 文档解析 / OCR 结构化作为前处理。

**Q11 怎么评测 Agent 效果？**
离线：评测集 + LLM-as-a-Judge（经人工校准）+ 规则断言；在线：一次性完成率、人工介入率、差错率、时长；问题回流：坏案例进评测集，改规则 / 知识 / 契约后回归。数字：Macro-F1 0.468 → 0.719；评估器人工校准。

**Q12 讲一个真实上线并持续运营的 AI 项目。**
楽天证券投资 AI 助手（实时 RAG、微调、GCP API、7×24）或 Canlah 社交营销 Agent（11 PR、18 Issue 后上线，SPF/DKIM/DMARC 与退信处理）。讲上线后的运营：监控、故障根因固化、指标变化。

**Q13 Function Calling / MCP 用过吗？**
MCP：Canlah 用 MCP 桥接把契约层暴露给所有 Agent；Function Calling：OpenAI / Claude API 实战。说明选 MCP 的原因（统一协议、多 Agent 复用）。
