### 高风险操作的人机边界（改价 / 退款 / 调账 / 房态变更）怎么答
- 分级：只读查询 → Agent 自动；低风险写操作（备注、标签）→ Agent 执行 + 事后抽检；高风险写操作 → Agent 生成"建议 + 依据 + 影响范围"，人审批后执行，审批链路按金额 / 影响分级
- 工具契约里显式声明副作用等级与是否可逆；幂等键防重复执行；所有写操作留痕（谁、何时、依据、审批人）
- 降级：LLM 不可用或置信度低 → 回退到规则或转人工，绝不"猜"
- 权限：Agent 以调用人的身份和权限执行，不给 Agent 超级权限

### 业务题预演
- 门店客诉退款场景：Agent 读订单 + 规则 → 判断是否符合退款条件 → 符合且金额 < 阈值：生成退款单待店长一键确认；超阈值：升级区域经理；全程留痕；指标：一次性完成率、人工介入率、处理时长
- 房态变更：高风险（影响收益），Agent 只提建议，人确认；接口幂等（同一请求重复调用只改一次）
- 门店差异化知识：总部 SOP 为基线版本，门店覆盖层单独版本管理；检索时按门店 ID 合并；变更走审核
