### 酒店域模型速成（能讲清"对象关联与状态流转"即可）

**PMS（物业管理系统）核心对象**
- Profile（客人档案）— Reservation（预订）— Room / RoomType（房间 / 房型）— RatePlan / Rate（价格计划 / 房价）— Folio（账单 / 账户）— Transaction（账务明细）— Night Audit（夜审）
- 预订状态流：询价 → 预订(Tentative) → 确认(Confirmed) → 到店入住(Checked-in) → 在住(In-house) → 退房结账(Checked-out)；分支：取消(Cancelled)、未到店(No-show)、提前离店、延住
- 房态：VC 空净 / VD 空脏 / OC 住净 / OD 住脏 / OOO 维修锁房 / OOS 暂停售卖。房态由客房部与前台共同流转，直接影响可售房量
- 房价体系：房型 × 价格计划 × 日期 = 房价；BAR 最优可用价、协议价、会员价、套餐价；限制条件（最少住几晚、提前几天、关房）
- 账务：入住开 Folio，消费入账（房费、餐饮、杂项），付款 / 挂账，退房结清；调账 = 冲正 + 重新入账，必须留痕
- 夜审（Night Audit）：每日营业日切换：自动过房费、处理 No-show、结转账务、生成日报（出租率、平均房价 ADR、RevPAR）。夜审期间禁止部分操作，是典型"高风险时段"

**CRS（中央预订系统）**
- 集团层面统一房量、房价、限制（ARI：Availability / Rate / Inventory）→ 分发到官网、APP、呼叫中心、OTA（携程、美团、Booking）
- 关键问题：房量同步与超售（Overbooking）、价格一致性（Rate Parity）、渠道对接（Channel Manager）、订单回流到 PMS
- 高风险操作：改价、关房、放量。错一次影响所有渠道

**神灯（智能客服 / 客需）**
- 客需 Request（送水、加床、报修、投诉、问路）→ 识别意图与紧急度 → 生成工单 Ticket → 分派 Dispatch（客房 / 工程 / 前台，按位置与负荷）→ 执行 → 回访 / 关闭
- SLA：响应时限、完成时限；超时升级（值班经理）；异常处置（无人接单、重复报修、投诉升级）
- Agent 化要点：意图识别 + 工具调用（查房态、建工单、查进度）；高风险（涉及退款 / 补偿 / 改价）转人工；指标：一次性完成率、人工介入率、平均响应 / 完成时长、差错率
- 德胧公开数据：试点店运营人员 18 → 12，房价 300 → 400

**会员（百达屋）**
- 会员等级 / 权益 / 积分（按入住时长计积分是百达屋特色）/ 券；会员 4,500 万+
- 营销触达 → 转化：分层、触达渠道（APP 推送、企微、短信）、活动、归因
- 高风险：积分调整、券发放 / 作废，需审批与留痕
