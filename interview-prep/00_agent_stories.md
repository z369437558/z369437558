# AI エージェント 2 本勝負（骨組み + 記入欄）

## なぜこの 2 本か

Stockmark の不採用理由（Uto 氏経由、9/26）：

> AI エージェント開発については、議論が比較的一般的なものにとどまり、
> **具体的な実装や改善提案といった過去のご経験から十分な具体例を得られなかった**。

そして 10/1 の Across Digital の CTO 面接でも、同じ質問が来た：
「**AI エージェント関連の経験・プロジェクトの有無**」。

2社が同じところを突いている。これは偶然ではなく、2026 年の AI 求人で最も聞かれる質問。
Loglass（10/5）・Ridge-i・Nohara（10/9）でも出る前提で用意する。

**ルールは 1 つ**：「エージェントを作りました」で終わらせない。
**固有名詞と数字が出るまで話す。** 出せないなら、その案件は使わない。

---

# STORY A ── 実装例（「何を作り、どこで壊れ、どう直したか」）

狙い：手を動かした人間にしか語れない失敗と対処を見せる。
ここで「ハルシネーションが課題でした」のような一般論を言うと、Stockmark と同じ結果になる。

## 記入欄（全部埋まるまでこの案件は使えない）

| # | 項目 | 記入 |
|---|---|---|
| A1 | 案件名・時期・自分の役割 | |
| A2 | **事業目的**（誰の、どの業務が、どう困っていたか。数字で） | 例：月◯件の◯◯業務に、1件あたり平均◯分 |
| A3 | なぜエージェントにしたか（単発 LLM 呼び出し／RAG／ルールベースで足りなかった理由） | |
| A4 | **定義したツール／関数を具体名で 3〜5 個**（例：`search_docs(query, top_k)`、`get_account(id)`） | |
| A5 | オーケストレーション方式（ReAct / plan-and-execute / 状態機械 / 多段）とその選択理由 | |
| A6 | モデル構成（どのモデルを、どの段で、なぜ。安いモデルと賢いモデルの使い分けは？） | |
| A7 | **壊れた箇所 ①**（ツール選択ミス／無限ループ／引数の捏造／文脈溢れ／権限超過 のどれか） | |
| A8 | ①をどう特定したか（ログ、トレース、評価セット。どうやって再現した？） | |
| A9 | ①をどう直したか（プロンプト？ツール設計変更？ガードレール？再試行制御？） | |
| A10 | **壊れた箇所 ②**（別の種類の失敗を 1 つ） | |
| A11 | ②の対処 | |
| A12 | 評価のやり方（何件の評価セット？成功の定義は？人手評価？自動？） | |
| A13 | **結果（定量）** 精度／成功率／処理時間／コスト／工数削減。ビフォーアフターで | |
| A14 | 本番運用で残っている課題（正直に 1 つ） | |

## 語る順番（2 分版）

1. **事業目的**（15秒）── A2。ここから始める。技術から始めない。
2. **なぜエージェント**（15秒）── A3。「単発の LLM 呼び出しでは◯◯が解けなかったため」
3. **構成**（30秒）── A4 + A5 + A6。ツール名を声に出す。ここで具体性が立つ。
4. **壊れた話**（40秒）── A7〜A11。**ここが一番大事。** 症状 → 特定方法 → 対処。
5. **結果**（20秒）── A12 + A13。数字。
6. **残課題**（10秒）── A14。正直に言うと信頼される。

## 60 秒版（時間がないとき）
A2 →「単発呼び出しでは解けないので、`◯◯` `◯◯` など N 個のツールを定義して
◯◯方式で回しました」→ A7 と A9（失敗を 1 つだけ）→ A13（数字）。

# STORY B ── 改善提案例（「自分が言い出して、通して、効果を出した」）

狙い：Across Digital が重視する「**指示待ちでなく自ら課題を見つけて動いた**」と、
Stockmark が取れなかった「**改善提案の具体例**」を同時に潰す。

**重要**：これは「技術的に良くした話」ではなく「**自分が提案者で、反対や無関心を乗り越えて通した話**」。
誰を説得したかが入っていないと、この STORY は機能しない。

## 記入欄

| # | 項目 | 記入 |
|---|---|---|
| B1 | 自分が気づいた問題は何か（**誰も問題だと思っていなかった**のが理想） | |
| B2 | どうやって気づいたか（ログを見ていて／ユーザーの声／コストの請求書／自分で使ってみて） | |
| B3 | **問題を数字にした**（例：◯◯のせいで月◯円／◯時間／失敗率◯%） ← 提案が通る鍵 | |
| B4 | 提案した変更（具体的に。「RAG を改善」ではなく「チャンク分割を◯◯から◯◯へ」） | |
| B5 | 検討した他の選択肢と、**なぜそれを選ばなかったか**（トレードオフ） | |
| B6 | **誰に提案したか**（上司／PO／業務部門／他チーム）と、相手の最初の反応 | |
| B7 | **どう納得させたか**（小さく試して数字を見せた？ コスト試算？ プロトタイプ？） | |
| B8 | 実行時に自分が担当した部分 | |
| B9 | **結果（定量）** ビフォーアフター | |
| B10 | その後どうなったか（他案件へ横展開された？ 標準になった？） | |

## 語る順番（2 分版）

1. **誰も見ていなかった問題**（20秒）── B1 + B2
2. **数字にした**（20秒）── B3。「◯◯を計測したら月◯◯でした」
3. **提案内容と、選ばなかった案**（30秒）── B4 + B5
4. **誰をどう巻き込んだか**（30秒）── B6 + B7。**ここを飛ばさない。**
5. **結果**（20秒）── B9 + B10

# 日本語の言い回し（そのまま使える）

**切り出し**
- 「エージェント構成の案件としては、◯◯が一番具体的にお話しできます。」
- 「まず背景からお話ししますと、◯◯という業務が月◯件あり、1件あたり◯分かかっていました。」

**なぜエージェントか**
- 「単発の LLM 呼び出しでは、◯◯を参照してから◯◯を判断する、という多段の処理が必要で、
  プロンプト 1 回では安定しませんでした。そこでツールを定義して段階的に解く構成にしました。」

**構成を具体的に**
- 「ツールとしては `◯◯` `◯◯` `◯◯` の3つを定義し、◯◯方式でオーケストレーションしています。」
- 「判断の段は◯◯、抽出の段は軽量な◯◯、とコストと精度でモデルを分けています。」

**失敗を語る（ここが差がつく）**
- 「一番手こずったのは◯◯でした。」
- 「ログを追うと、◯◯のケースで必ず◯◯を選んでしまっていることが分かりました。」
- 「再現する入力を◯件集めて評価セットにし、修正の前後で比較しました。」
- 「対処としては、プロンプトではなく**ツールの設計自体**を変えました。具体的には◯◯です。」

**結果**
- 「結果として、◯◯が◯%から◯%に改善し、1件あたり◯分→◯分になりました。」
- 「月あたりのコストは◯円から◯円に下がっています。」

**正直に言う（信頼される）**
- 「ただ、◯◯については今も完全には解けておらず、現状は人のレビューを挟んでいます。」

**提案の話（STORY B）**
- 「これは依頼されたものではなく、◯◯を見ていて気づいて、自分から提案しました。」
- 「最初は◯◯という反応でしたので、まず小さく試して数字を出し、それを持って再度説明しました。」

# 想定される深掘り質問（答えを用意しておく）

1. なぜ ReAct（あるいは選んだ方式）にしたのか。他の方式と比べて何が良かったか
2. ツールの数は何個か。増えすぎたときツール選択の精度はどうなったか
3. エージェントが暴走しない・無限ループしない仕組みは
4. 権限が必要な操作（書き込み・外部送信・決済など）はどう扱ったか
5. どうやって評価したか。評価セットは何件、成功の定義は何か
6. コストはどう管理したか。1リクエストいくらか
7. レイテンシは。ユーザーは待てたのか
8. 本番で想定外だったことは
9. 今同じものを作り直すなら、どこを変えるか ← **これは必ず用意する。視点の高さが出る**
10. フレームワーク（LangGraph / 自作など）は何を使ったか。なぜ

# やってはいけないこと（Stockmark で落ちた型）

| ❌ | ⭕ |
|---|---|
| 「エージェントを使ったプロジェクトをやりました」 | 「`search_docs` など3つのツールを定義し、◯◯方式で回しました」 |
| 「ハルシネーションが課題でした」 | 「◯◯の入力で必ず◯◯のツールを誤選択していました。ログで特定し、ツールの説明文を◯◯に変えて解消しました」 |
| 「精度を改善しました」 | 「◯件の評価セットで、成功率◯%→◯%」 |
| 失敗談に**技術的な失敗**を選ぶ | 失敗談に**判断・優先順位・合意形成の失敗**を選ぶ |
| 自分から技術の細部に潜る | 事業目的から入り、細部は聞かれてから出す |

# 使い方

1. 上の表を埋める。**数字が埋まらない欄は、その案件がその質問に耐えないというサイン**。
   別の案件に差し替えるか、今のうちに実際の数字を確認しておく。
2. 埋めたら、2分版を声に出して時間を計る。2分を超えるなら細部を削る（削るのは構成の話、残すのは失敗と数字）。
3. 10/5 Loglass、10/9 Nohara の前夜にこのファイルだけ読み返す。
